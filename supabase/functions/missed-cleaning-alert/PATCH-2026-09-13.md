# missed-cleaning-alert — add the meter photo section (v23 → v24)

Lloyd, 2026-09-13: *"a message to telegram should be sent in addition to
missing cleaning checklist reminder"*.

The 08:00 Manila cron already chases missing cleaning reports. A report that
arrived but whose meter photo was skipped, or which the vision check
disagreed with, is the same class of problem — a turnover nobody can verify —
so it belongs in the same morning message rather than a second alert nobody
would subscribe to.

**Read D-085 before editing this function's live source.** The Apps Script
lesson applies to edge functions too: read the deployed source back before
overwriting it, because the deployed copy is the source of truth.

This is a patch note rather than a replacement file, because the function is
deployed from a folder that also carries `_shared/observability.ts` and
`_shared/redaction.ts`, which this repo does not vendor.

## What to change

### 1. Move the early return

`rows.length === 0` currently returns before anything else runs. Move that
early return **below** the new block, or the meter section never runs on a
morning when every cleaning report is present — which is precisely the
morning it matters.

### 2. After the existing `rows` loop

```ts
    // ── Meter photos that still need attention (2026-09-13) ──────────────
    // Same morning message, same OPS group. A report whose meter photo was
    // skipped, or which the vision check disagreed with, is an unverifiable
    // turnover exactly like a missing report — chased the same way.
    //
    // Deliberately quiet about blame: 'unreadable' is usually a dark photo,
    // not a dishonest one, so it is reported as something to look at rather
    // than something someone did.
    const { data: followups, error: fErr } = await supabase
      .rpc('get_meter_photo_followups', { p_property_id: propertyId, p_lookback: 14 });

    if (fErr) {
      // A missing function means the 2026-09-13 migration is not applied yet.
      // The missing-report alert above still went out; note it and move on.
      console.warn('[missed-cleaning] meter follow-up RPC unavailable:', fErr.message);
    } else if ((followups ?? []).length > 0) {
      const lines = (followups as Array<Record<string, unknown>>).slice(0, 5).map((f) => {
        const when = fmtDate(String(f.cleaned_at ?? '').slice(0, 10));
        const who  = (f.cleaner_name as string) || 'unknown cleaner';
        const why  = (f.reason as string) || 'needs another look';
        const seen = f.vision_verdict === 'mismatch' && f.vision_electric != null
          ? ` — photo reads ${f.vision_electric}, report says ${f.typed_electric ?? '—'}`
          : '';
        return `• ${when} · ${who}: ${why}${seen}`;
      });

      await tgSend(TG_TOKEN, TG_CHAT_ID, [
        `👀 *Meter photos needing a look*`,
        `🏠 Cascade Hideaway`,
        ``,
        ...lines,
        ``,
        `_The cleaner is asked to re-upload at her next sign-in. Worth checking before the cleaning fee is paid._`,
      ].join('\n'));
    }
```

### 3. Widen the return

```ts
    return json({ ok: true, missed: rows.length, meter_followups: (followups ?? []).length });
```

### 4. Nothing else changes

Same env vars (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`), same
`withObservability({ route: 'ops' })` wrapper, same cron job 7. No new secrets.

## Order of operations

`get_meter_photo_followups` must exist first, or the new block logs a warning
and does nothing — harmless, but pointless. Apply
`sql/2026-09-13-meter-vision-and-photo-skip.sql` before deploying this.
